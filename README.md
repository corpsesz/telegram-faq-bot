# Telegram FAQ-бот «НеонЛофт»

Навчальний проєкт: Telegram-бот для вигаданої студії цифрового дизайну
«НеонЛофт». Бот показує послуги та ціни, графік роботи, адресу і відповіді
на часті питання.

Стек: Python 3.11+ та aiogram 3.

## ⚠️ Усі дані — вигадані

**Студія, адреса, контакти, ціни, графік роботи та відповіді на питання
придумані виключно для демонстрації.**

- «НеонЛофт» — не існуюча студія.
- Адреса, телефон, пошта та Telegram-акаунт — вигадані, не прив'язані до
  жодної реальної компанії чи людини.
- Ціни в гривнях — вибіркові round-числа для прикладу, не ринкові пропозиції.
- Пошта має домен `.example`, зарезервований RFC 2606 для прикладів і
  прикладів — його не може бути в реальному використанні.

Жодних персональних даних у проєкті немає. Токен бота зберігається лише у
файлі `.env`, який не потрапляє в git.

## Можливості (етап 1)

- Привітання та головне меню з кнопками
- Розділ «Послуги та ціни» — перелік послуг із цінами
- Розділ «Часті питання» — 6 питань із відповідями
- Розділ «Графік роботи»
- Розділ «Адреса студії»
- Розділ «Зв'язатися»

Бот працює лише на читання: він не зберігає дані користувачів, не
використовує базу даних і не приймає оплату.

## Встановлення та запуск у Windows PowerShell

Відкрийте PowerShell у папці проєкту `telegram-faq-bot`.

### 1. Створіть віртуальне оточення

```powershell
python -m venv .venv
```

### 2. Активуйте оточення

```powershell
.\.venv\Scripts\Activate.ps1
```

Якщо PowerShell блокує запуск скрипта, дозвольте локальні скрипти для
поточного користувача один раз:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Або активуйте оточення без зміни політики — без активації:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m bot
```

### 3. Встановіть залежності

```powershell
pip install -r requirements.txt
```

### 4. Створіть файл `.env`

```powershell
Copy-Item .env.example .env
```

Відкрийте `.env` у редакторі й підставте власний токен від
[@BotFather](https://t.me/BotFather):

```ini
BOT_TOKEN=1234567890:AAExampleTokenReplaceMe
BOT_NAME=НеонЛофт
```

Файл `.env` додано до `.gitignore` і він не потрапляє в репозиторій.

### 5. Запустіть бота

```powershell
python -m bot
```

Бот запрацює в режимі long polling: відкрийте чат із ботом у Telegram
і надішліть `/start`.

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m bot
```

## Як усе влаштовано

- **Обробники** підключаються в `bot/__main__.py` через `Dispatcher`.
  Команда `/start` ловиться фільтром `CommandStart`, кнопки — за
  `callback_data`.
- **Клавіатури** збираються в `bot/keyboards/main.py`. Скрізь використовується
  `callback_data`, а не текст: так перейменування кнопки не ламає логіку.
- **Тексти** лежать у `bot/content.py`. Щоб змінити ціну, графік роботи
  чи адресу, редагуйте лише цей файл.
- **Повторні натискання** обробляються в `bot/utils.py`: Telegram відповідає
  помилкою «message is not modified», якщо текст не змінився — цей випадок
  ловиться і не ламає бота.
- **Форматування** задається один раз у `build_bot()` у `bot/__main__.py`:
  `DefaultBotProperties(parse_mode="HTML")`. У aiogram 3 параметр
  `parse_mode` не можна передати в конструктор `Bot` напряму — лише через
  `default=`. Тепер у текстах можна писати `<b>жирний</b>`, і Telegram
  відмалює розмітку, а не покаже теги.

## Перевірка

Тест проганяє всі обробники через mock-сесію (без звернення до Telegram
API) — перевіряються тексти, клавіатури, повторні натискання та те, що
кожен запит іде з `parse_mode="HTML"`:

```powershell
python tests\test_handlers.py
```
